# BUG-002. После смены сортировки список оказывается в конце

| | |
| --- | --- |
| Серьёзность | Major — пользователь думает, что сортировка не работает |
| Приоритет | P2 |
| Происхождение | Найден автотестом при первом прогоне |
| Окружение | Pixel 6 (эмулятор), Android 15 / API 35, arm64; debug-сборка 1.0.0; сервер — stub-server |
| Статус | Исправлен, закрыт регрессионным тестом |

**Шаги**
1. Открыть каталог (вверху «Смартфон Samsung Galaxy A56», 189 990 ₸).
2. Сортировка → «Сначала дешевле».

**Ожидание:** список сначала, первый — «Курт солёный, 300 г», 2 490 ₸.
**Факт:** экран прокручен в самый низ, видны самые дорогие товары и «Товаров: 18».

**Доказательство:** [скриншот](img/BUG-002-sort-list-at-end.png).

**Причина:** `LazyColumn` сохраняет позицию по ключу первого видимого элемента. Ключ — id товара.
Смартфон был первым, после сортировки по цене он последний, и список «поехал» за ним.
Тот же эффект при смене категории и поиска.

**Исправление:** у результата поиска есть номер поколения; когда приходит список с другими фильтрами,
экран прокручивается к началу. Номер просмотренного поколения хранится в `rememberSaveable`, поэтому поворот экрана
и обновление свайпом позицию не сбрасывают — [CatalogScreen.kt](../../../app/src/main/java/kz/duken/mobile/ui/catalog/CatalogScreen.kt).

**Регрессия:** `test_catalog.py::test_sort_by_price`, `test_lifecycle.py::test_catalog_filters_survive_rotation`.
