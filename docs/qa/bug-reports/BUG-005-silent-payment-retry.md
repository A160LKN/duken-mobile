# BUG-005. HTTP-клиент сам повторяет оплату после обрыва связи

| | |
| --- | --- |
| Серьёзность | Critical — риск ошибки «не оплачено» при списанных деньгах |
| Приоритет | P1 |
| Происхождение | Найден автотестом с имитацией обрыва соединения |
| Окружение | Pixel 6 (эмулятор), Android 15 / API 35, arm64; debug-сборка 1.0.0; сервер — stub-server |
| Статус | Исправлен, закрыт двумя регрессионными тестами |

**Шаги**
1. Оформить заказ, открыть оплату.
2. Заглушка рвёт соединение на `POST /orders/{id}/pay` (`fault drop=true`).
3. Нажать «Оплатить».

**Ожидание:** «Нет подключения к интернету»; повтор — только по кнопке.
**Факт:** ошибки нет, оплата проходит. Журнал заглушки:
```
POST /orders/1/pay   0     ← соединение оборвано
POST /orders/1/pay   200   ← повтор, который пользователь не нажимал
```

**Чем опасно:** если сервер успел списать деньги и потерялся только ответ, тихий повтор получает
409 «заказ уже оплачен», и приложение показывает ошибку при оплаченном заказе. Покупатель платит ещё раз другой картой
или идёт в поддержку.

**Причина:** у OkHttp `retryOnConnectionFailure = true` по умолчанию — повторяются и неидемпотентные POST.

**Исправление** — [ApiClient.kt](../../../app/src/main/java/kz/duken/mobile/data/api/ApiClient.kt),
[PaymentScreen.kt](../../../app/src/main/java/kz/duken/mobile/ui/payment/PaymentScreen.kt):
1. `retryOnConnectionFailure(false)`.
2. На 409 `invalid_status` при оплате приложение перечитывает заказ; если он оплачен — показывает успех.

**Регрессия** (`test_network.py`):
- `test_network_lost_during_payment` — обрыв до обработки: ошибка, повтор кнопкой, ровно 2 запроса и 1 списание;
- `test_payment_response_lost_after_charge` — сервер списал, ответ потерян (`fault drop_after=true`):
  повтор показывает успех, списание одно.

**Последствие исправления:** первое исправление отключало автоповтор во всём клиенте и сломало безопасный повтор
чтения после закрытого сервером соединения — [BUG-012](BUG-012-stale-connection-offline.md). Итоговое решение —
два клиента: без автоповтора только для оплаты, создания и отмены заказа и регистрации.
