# Дүкен — мобильное приложение магазина и его тестирование

Нативное Android-приложение (Kotlin, Jetpack Compose) — клиент к API [shop-api](https://github.com/A160LKN/shop-api),
и полный цикл мобильного QA к нему: тест-план, чек-листы, автотесты на Appium, баг-репорты, CI на эмуляторе.

Главное здесь — то, чего нет в вебе: поворот экрана, гибель процесса в фоне, обрыв сети посреди оплаты,
системная кнопка «Назад», разрешения Android 13+, ссылки из других приложений, TalkBack, крупный шрифт.

Эмулятор Pixel 6, Android 15 (API 35). Полный прогон E2E — около 8 минут.

**Честный статус стабильности.** Четыре полных локальных прогона после исправлений: три прошли целиком
(последний — 168/168), в одном упал один тест — не на проверке: служба UiAutomator2 на эмуляторе не ответила 240 секунд. Отдельно этот тест
проходит стабильно (3 из 3), в следующих двух полных прогонах сбой не повторился. Причина не установлена — журнал
Appium тогда писался на уровне `warn`; уровень поднят до `info`, чтобы следующий такой случай можно было разобрать.
Автоматических перезапусков упавших тестов нет намеренно.

**CI.** Первый прогон: сборка прошла, E2E с заглушкой — 165/167, смоук против shop-api — 1/3. Эмулятор в CI
(x86, программная отрисовка) заметно медленнее локального — он и выявил BUG-010 и BUG-011; тестовая обвязка
доработана под медленное устройство. Текущий статус — значок CI в репозитории.

## Найденные дефекты

11 баг-репортов в [docs/qa/bug-reports](docs/qa/bug-reports/README.md): шаги, ожидание и факт, доказательство
(скриншот, журнал запросов, стек), причина, исправление, регрессионный тест.

- **Восемь нашли автотесты** — их никто не закладывал: шесть при первых прогонах на эмуляторе, два в первом прогоне CI
  на медленном эмуляторе x86. Среди них:
  - HTTP-клиент сам повторял `POST /pay` после обрыва связи; при потерянном ответе покупатель видел бы ошибку
    при списанных деньгах (Critical);
  - каждая ссылка `duken://` открывала вторую копию приложения поверх первой;
  - TalkBack не сообщал число товаров в корзине — Material 3 убирал значок из дерева доступности;
  - после сортировки список оказывался в конце — `LazyColumn` держался за товар по ключу;
  - клавиатура закрывала поле промокода и кнопку «Оформить заказ» — режим edge-to-edge без отступа под клавиатуру.
- **Три заложены в версию 1.0 намеренно** — самые частые ошибки мобильных приложений, чтобы показать, что тесты
  их ловят: промокод пропадает при повороте, падение на оплате после гибели процесса, «Назад» после оплаты — ловушка.
  Одну из них первая версия теста пропустила; тест усилен, это описано в отчёте.

## Как устроены тесты

- **Сервер-заглушка** [stub-server](stub-server/server.py) повторяет контракт shop-api на стандартной библиотеке Python.
  Тест сам включает сбой: ответ 500/503, задержку, обрыв соединения до обработки и после неё (`drop_after` —
  сервер списал, ответ потерян), истёкший токен, изменение остатка. Смоук в CI идёт против настоящего shop-api в Docker.
- **Чистое приложение на каждый тест:** `pm clear`, сброс заглушки, очистка logcat. Покупатель создаётся через API.
- **Вход тестовым хуком** debug-сборки (`--es test_token`), а не через UI в каждом тесте; UI входа проверяется отдельно.
  В release хуков нет — это проверяет статический тест.
- **Локаторы — `resource-id` из `testTag` Compose** (`testTagsAsResourceId`), без XPath по тексту.
  Всплывающие меню — отдельный корень Compose, им флаг ставится отдельно.
- **Устройство — через adb:** авиарежим с ожиданием фактического состояния сети, `am kill` в фоне (так система
  освобождает память), ориентация, размер шрифта, тёмная тема, язык приложения, выдача и отзыв разрешений.
- **Падение приложения проваливает тест**, даже если проверки прошли: фикстура читает буфер `crash` logcat.
- **Артефакты при падении:** скриншот, дерево UI и logcat во вложениях Allure.

## Запуск

Нужны JDK 17, Android SDK с эмулятором, Node.js и Python 3.

```bash
npm install && npm run appium:driver          # Appium 4 и драйвер UiAutomator2 — в проект, не глобально
./scripts/run-local.sh                        # эмулятор, сборка, заглушка API, Appium, все тесты
./scripts/run-local.sh -m smoke               # только основной путь покупки
./gradlew testDebugUnitTest                   # юнит-тесты
maestro test maestro/                         # смоук на Maestro (нужны эмулятор и python3 stub-server/server.py)
```

Эмулятор `duken_api35` создаётся один раз:
`avdmanager create avd -n duken_api35 -k "system-images;android-35;google_apis;arm64-v8a" -d pixel_6`.

## CI

[GitHub Actions](.github/workflows/ci.yml): сборка, юнит-тесты, lint и debug/release APK → E2E на эмуляторе
Android 15 (x86_64 + KVM) с заглушкой → смоук против настоящего shop-api в Docker Compose.

## Стек приложения

Kotlin 2.1 · Jetpack Compose (Material 3) · Navigation Compose · ViewModel + SavedStateHandle · Room (корзина) ·
DataStore (сессия) · Retrofit + OkHttp + kotlinx.serialization · minSdk 26, targetSdk 35 · русский и казахский.

## Не входит

iOS · реальные платежи · push с сервера · планшеты и складные устройства · тест обновления поверх старой версии
(в приложении одна версия схемы БД — мигрировать нечего).
