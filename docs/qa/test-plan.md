# Тест-план: мобильное приложение «Дүкен» для Android

## 1. Объект тестирования

Нативное Android-приложение магазина (Kotlin, Jetpack Compose) — клиент к API [shop-api](https://github.com/A160LKN/shop-api).
Вход и регистрация, каталог с поиском, фильтром и сортировкой, карточка товара, корзина на устройстве (Room),
промокоды, оформление и оплата заказа, история заказов, отмена, ссылки `duken://product/{id}`,
уведомление об оплате, русский и казахский языки.

Версия под тестом: 1.0.0 (versionCode 1), debug-сборка с тестовыми хуками; release — для проверки отсутствия хуков.

## 2. Что проверяется в мобильном приложении сверх веба

| Риск | Почему важен на телефоне | Как проверяется |
| --- | --- | --- |
| Поворот экрана пересоздаёт Activity | Введённые данные и выбор теряются | `test_lifecycle.py::TestRotation` |
| Система убивает процесс в фоне | Пользователь ушёл в банк или мессенджер — вернулся в пустой или упавший экран | `adb shell am kill` в `TestBackground` |
| Сеть пропадает и возвращается | Метро, лифт, Wi-Fi → LTE | авиарежим на эмуляторе, обрыв соединения на сервере |
| Медленный ответ | Зависание интерфейса (ANR) | задержка на заглушке API |
| Системная кнопка «Назад» | Возврат на экран оплаты, выход из аккаунта «назад» | `driver.back()` |
| Разрешения Android 13+ | Отказ ломает сценарий; навязчивый запрос | системный диалог в `test_permissions.py` |
| Ссылки из внешних приложений | Открытие до входа, неверный id, «Назад» | `am start -d duken://…` |
| Размер шрифта, тёмная тема, язык | Текст уезжает, кнопки за экраном | `font_scale 2.0`, `cmd uimode night`, `set-app-locales` |
| Доступность | TalkBack, размер области нажатия | разбор дерева UI: подпись и 48 dp |
| Обновление приложения | Потеря корзины при миграции БД | **не проверяется**: одна версия схемы БД — мигрировать нечего |

## 3. Уровни тестирования

| Уровень | Инструмент | Где запускается |
| --- | --- | --- |
| Юнит (JVM) | JUnit 4, MockWebServer, coroutines-test | `./gradlew testDebugUnitTest`, CI |
| Статические проверки | pytest без устройства: переводы, плейсхолдеры, network security config, release без хуков | CI, секунды |
| E2E (UI) | Appium 4 + UiAutomator2, Python, pytest, Page Object, Allure | эмулятор Android 15 локально и в CI |
| Смоук без кода | Maestro (YAML) | локально по желанию |
| Ручное | чек-листы `checklists/` | эмулятор, реальное устройство |

## 4. Окружения

| | Локально | CI (GitHub Actions) |
| --- | --- | --- |
| Устройство | эмулятор Pixel 6, Android 15 (API 35), arm64 | эмулятор Pixel 6, Android 15, x86_64 + KVM |
| Сервер | заглушка `stub-server/` (Python stdlib) | заглушка; смоук — настоящий shop-api в Docker Compose |

Почему заглушка: тест сам включает сбой (500, обрыв соединения, задержка, истёкший токен), меняет остаток товара
и сбрасывает данные между тестами. Контракт заглушки совпадает с shop-api; расхождение ловит смоук против настоящего API.

## 5. Тестовые данные

- Покупатель создаётся через API в каждом тесте (`buyer-<uuid>@test.kz`) — тесты не зависят друг от друга.
- Каталог — 18 товаров из seed shop-api; товар 6 закончился, у товара 4 остаток 4.
- Промокоды: `WELCOME10` (−10 %), `BIG20` (−20 % от 100 000 ₸).
- Тестовые карты: `tok_visa` — оплата проходит, `tok_declined` — отказ банка, `tok_timeout` — шлюз не отвечает 5 с → 502.

## 6. Изоляция и стабильность автотестов

- Перед каждым тестом: `pm clear` (данные, язык, разрешения), сброс заглушки, очистка logcat.
- Вход — тестовым хуком debug-сборки (`--es test_token`), а не через UI в каждом тесте: UI входа проверяется отдельно.
- Локаторы — `resource-id` из `testTag` Compose (`testTagsAsResourceId`), без XPath по тексту.
- Явные ожидания условий, без `sleep` в тестах.
- Падение приложения во время теста (буфер `crash` в logcat) — провал теста, даже если проверки прошли.
- При падении — скриншот, дерево UI и logcat во вложениях Allure.

## 7. Критерии

**Начало:** приложение собирается, юнит-тесты зелёные, эмулятор загружен.
**Окончание:** все E2E проходят на заглушке и смоук — на настоящем shop-api; найденные дефекты закрыты
регрессионными тестами или описаны с решением «не исправлять» и причиной.

## 8. Не входит

iOS; реальные платежи; push с сервера (уведомление локальное); планшеты и складные устройства;
производительность на слабых устройствах — проверено только время запуска на эмуляторе.
