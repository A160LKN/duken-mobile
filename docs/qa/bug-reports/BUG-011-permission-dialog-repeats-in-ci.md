# BUG-011. На медленном устройстве диалог разрешения появляется повторно

| | |
| --- | --- |
| Серьёзность | Minor — лишний системный диалог; нажатие может прийти в кнопку под ним |
| Приоритет | P3 |
| Происхождение | Найден автотестом в первом прогоне CI (эмулятор x86 с программной отрисовкой) |
| Окружение | GitHub Actions, ubuntu-latest, эмулятор Pixel 6, Android 15 x86_64 |
| Статус | Исправлено вероятное место; локально не воспроизводился |

**Шаги:** чистая установка → первая оплата → в диалоге уведомлений нажать «Don't allow».

**Ожидание:** экран «Заказ оплачен», уведомлений нет.
**Факт (CI):** открыта вкладка «Заказы», поверх снова диалог разрешения. Кнопка «Мои заказы» на экране успеха стоит ровно
под кнопкой «Don't allow»: диалог закрылся и открылся снова, и нажатие пришло в кнопку под ним.

**Вероятная причина:** разрешение запрашивал экран оплаты в тот же момент, когда уходил из стека. Во время анимации
перехода на медленном устройстве запрос мог выполниться повторно. Полностью подтвердить не удалось: logcat из CI не
содержит событий запуска диалога, локально на arm64 сбой не воспроизводится.

**Исправление:** запрос перенесён на экран успеха, который остаётся на месте, и выполняется один раз за экран
(флаг в `rememberSaveable`, в том числе после поворота) —
[PaymentScreen.kt](../../../app/src/main/java/kz/duken/mobile/ui/payment/PaymentScreen.kt).

**Регрессия:** `test_permissions.py::test_deny_keeps_app_working`; результат — по следующему прогону CI.
