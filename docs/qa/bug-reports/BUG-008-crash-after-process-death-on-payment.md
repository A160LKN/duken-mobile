# BUG-008. Падение при возврате на оплату после гибели процесса

| | |
| --- | --- |
| Серьёзность | Critical — падение на шаге оплаты |
| Приоритет | P1 |
| Происхождение | Заложен в версию 1.0 намеренно (типичная ошибка), пойман автотестом |
| Окружение | Pixel 6 (эмулятор), Android 15 / API 35, arm64; debug-сборка 1.0.0; сервер — stub-server |
| Статус | Исправлен, закрыт регрессионным тестом |

**Шаги**
1. Оформить заказ, открыть экран оплаты.
2. Свернуть приложение (ушли в банковское приложение за кодом).
3. Система освобождает память — `adb shell am kill kz.duken.mobile`.
4. Вернуться в приложение из недавних.

**Ожидание:** та же форма оплаты того же заказа. **Факт:** приложение падает
([стек](img/BUG-008-crash.txt)):
```
java.lang.NullPointerException
  at kz.duken.mobile.ui.payment.PaymentViewModel.<init>(PaymentScreen.kt:69)
```

**Причина:** заказ передавался на экран оплаты через объект в памяти (`CheckoutHolder`). Android восстанавливает стек
экранов после гибели процесса, а объект в памяти — нет.

**Исправление:** маршрут `payment/{orderId}` — id хранится в состоянии навигации, заказ читается с сервера;
если он уже оплачен, сразу показывается успех. `CheckoutHolder` удалён —
[PaymentScreen.kt](../../../app/src/main/java/kz/duken/mobile/ui/payment/PaymentScreen.kt).

**Регрессия:** `test_lifecycle.py::test_process_death_on_payment_screen`; фикстура `app` проваливает любой тест,
если в буфере `crash` logcat есть падение приложения.
